# 小橘 Live2D 实施 PRD v2.1

> 状态：小橘专用实施方案，当前停在 X6 分层重组、参数、Motion 与 Action Tracer 候选。本文不替代通用 `rig-live2d-pet` Skill，也不授权越过当前 Gate 做 X7 Physics、PSD/Cubism 或运行时。

## 1. 文档边界

通用 Skill 负责任何角色都适用的 Gate、ArtMesh、节点树、弹性链、Action Tracer、运行时与 QA 方法。本 PRD 只负责小橘的身份、猫科结构、星球接触、登录动作、参数目标和验收证据。

## 2. 目标模型

- `XiaojuRoot`：完整小橘，从耳尖到尾尖包含头脸、颈胸、四肢、四爪、腹部、骨盆、尾巴和所有默认隐藏结构。
- `PlanetRoot`：完整星球，包含后层、表面、前景边缘、漂浮、微旋转和遮挡区域。
- 两者必须可以独立审计、独立开关和独立驱动。
- 最终是一包双 Root 还是两个模型，留到架构试片决定；不得提前把“逻辑独立”误写成固定文件数量。

## 3. 权威输入与淘汰项

权威输入：`three-view-preview.png` 负责小橘身份与比例；原登录场景负责摄像机、构图、星球接触意图和氛围。

淘汰：v5 混合身体与 `parts-v5`。仅参考：v7 连续猫、旧眨眼/目光技术试验。暂停：v5 PSD 导入脚本。旧 `.cmo3/.moc3` 只作历史兼容参考。

## 4. 小橘专用产出阶段

### X0：冻结身份和动作范围

首批动作仅为 `idle`、邮箱聚焦、密码遮眼进入/保持/退出。微动作包括眨眼、目光、眼睑跟随、呼吸、耳朵、尾巴、胡须和身体回稳。不得用整图切换或独立 PNG 解剖动画。

### X1：三视图统一身体

在三视图标注同名点：头骨、下颌、颈根、双肩胛、肩、肘、腕、前爪心、肋笼、腹部、骨盆、髋、膝、跗、后爪心和尾根至尾尖节点。建立一套近似 3D 骨架、固定骨段长度、关节范围、左右与深度关系。

质量块至少包含头、肋笼、腹部和骨盆。目标视角中的同一身体必须能回投解释三视图；不得为登录姿势重新发明另一只猫。

### X2：星球支撑与遮眼动作求解

明确胸腹—星球接触带、法线、摩擦/允许滑动、重心、支撑反力和前爪释放顺序。遮眼链固定为肩胛 → 肩 → 肘 → 腕 → 爪心；抬爪时身体只能有低幅反向补偿，不能压缩肋笼或骨盆。

交付至少 41 个采样点的 `Rest -> Cover -> Rest` 连通块面。检查 IK 分支、骨段长度、质量块体积、爪心轨迹、胸腹接触和重心支撑。

### X2.5：图形学流程修正（知乎文章约束）

用户指定参考知乎文章《Live2D动画引擎的图形学原理及实现》（`https://zhuanlan.zhihu.com/p/383268858`）。后续流程必须按图层、网格、节点、弹性的真实依赖顺序执行：

1. X2 只验证星球支撑、遮眼动作、接触、重心、物理力矩和控制力矩，不生成正式分层图，也不提前打正式三角剖分点。
2. X3 必须先从 X1/X2 批准身体制作完整连通的大字型/展开三视图母版，用于确认小橘全身、隐藏结构、左右身份和体积连续性。
3. X4 才能从 X3 批准母版细致拆出真实语义图层；分层图片必须足够完整，能暴露后续网格边界、遮挡安全重叠和隐藏补全。
4. X5 才能对每个真实图层边界建立三角网格，采用 Delaunay/三角图元原则准备 ArtMesh 点集；不得在 X2 块面上伪造最终网格。
5. 每个真实图层拥有一个主控制节点，节点再形成父子骨骼树；父级变换级联到子级，局部节点不得反向拖动父级。
6. 弹性系数属于三角网格顶点级的后续模拟；远离主节点的软组织顶点可有更高弹性和阻尼差异，但解剖支点和骨段长度必须稳定。
7. 视觉摆动、软组织拉伸和回弹不得通过改变骨段长度实现。

### X3：完整连续大字型/展开三视图母版

依据 X1/X2 的批准投影制作一只完整、连通、无星球遮挡的小橘大字型/展开三视图母版，再叠回星球验证。该母版负责统一头身比例、耳朵、四肢、尾巴、腹胸骨盆、隐藏结构和默认遮挡关系，是后续分层图片的唯一图像来源。禁止混拼不同姿势、不同生成版本或旧登录头部。

### X4：小橘与星球拆层

小橘最低拆层范围：

- 头骨体、口鼻/下颌、左右脸颊毛；
- 左右耳根、耳面、耳尖；
- 左右眼白/虹膜/瞳孔/高光/上下眼睑与眼眶遮罩；
- 颈、胸、肋笼、腹部、骨盆；
- 左右肩胛遮挡、上臂、前臂、腕、前爪；
- 左右大腿、小腿/跗、后爪；
- 尾根、尾中、尾尖；
- 胸毛、脸颊毛、胡须束等次级区域。

星球最低拆层范围：后层、主体表面、接触阴影、前景边缘和可独立漂浮装饰。所有关节与遮挡边必须有隐藏纹理和安全重叠。

拆层必须从 X3 批准的大字型/展开母版产生。每个图层都要保留足够边界点、重叠区、隐藏补全和材质连续性，以便 X5 可以在真实图层边界内做三角剖分；不得先做网格再反推图层。

### X5：Layer-Mesh-Node 合同

按通用 Skill 模板为每一层填写 ArtMesh、主控制 Deformer、父节点、真实支点、网格加密区、隐藏重叠、Draw Order/Clipping、主动参数和弹性输出。X5 的网格点必须来自 X4 真实图层边界和内部辅助点，先以三角图元/Delaunay 原则形成可变形面，再分配节点权重、软组织弹性系数和阻尼。

小橘主树至少为：

```text
XiaojuRoot
  BodyRoot
    Ribcage / Abdomen / Pelvis
    Neck -> Head -> Eyes / Ears / Muzzle
    Scapula_L/R -> Shoulder -> Elbow -> Wrist -> ForePaw
    Hip_L/R -> Knee -> Hock -> HindPaw
    TailRoot -> TailMid -> TailTip

PlanetRoot
  PlanetBody
    PlanetBack / ContactShadow / PlanetFront / Decorations
```

父节点测试必须证明：身体带动四肢和头；局部关节不反向拖动父体；星球独立移动不改变小橘骨段。每个真实图层只能有一个主控制节点，但可在该图层网格内拥有辅助顶点、权重区和弹性顶点；这些辅助点服务于变形，不等同于新增骨段。

### X6：参数、Motion 与 Action Tracer

登录输入链：

```text
登录状态/有效关注目标
  -> 优先级选择
  -> 模型局部坐标
  -> 眼眶安全椭圆与指针关注区
  -> 速度/加速度限制与平滑
  -> 眼球先行
  -> 头部延迟跟随
  -> 身体低幅补偿
  -> Deformer 级联
```

优先级：密码遮眼接触 > 明确交互目标 > 当前输入框 > 小橘附近指针 > idle 环境观察。目标切换保留眼球、头部和身体的当前速度，不先跳回中心。

遮眼主动 Motion 由独立的肩、肘、腕、爪心和身体补偿曲线组成；左右爪允许小幅错时，但最终必须自然覆盖双眼。Physics 不得决定遮眼核心轨迹。

#### X6.1 小橘眼部素材与节点

左右眼分别保留：无瞳孔眼底/眼眶底、虹膜、瞳孔、高光、上眼睑、下眼睑、眼角与眼眶毛遮挡、Clipping Mask 和闭眼线。原图眼底中不得残留第二套黑瞳或重复高光。

节点关系：

```text
Head
  EyeSocket_L/R
    EyeMask_L/R
    Iris_L/R -> Pupil_L/R -> Highlight_L/R
    UpperLid_L/R
    LowerLid_L/R
    EyeFurOccluder_L/R
```

虹膜与瞳孔共享主要目光方向；高光移动幅度小于虹膜并保持同一光源。眼睑拥有自己的眨眼形变，同时以低权重跟随纵向目光。任何极值下虹膜、瞳孔和高光都不得离开眼眶安全遮罩。

#### X6.2 小橘眼部参数

初始参数合同至少包含：

| 通道 | 参数 | 初始范围/规则 |
| --- | --- | --- |
| 共同目光 | `ParamEyeBallX/Y` | `-1..1`，双眼同向主目标 |
| 左右开合 | `ParamEyeLOpen/ROpen` | `0..1`，不承载目光方向 |
| 主眨眼 | `ParamBlink` | `0..1`，调度器输出后分配至左右眼 |
| 轻微会聚 | `ParamEyeConvergence` | `0..0.08`，只用于近距离目标 |
| 眼睑跟随 | `ParamEyeLidFollowY` | 目光 Y 的约 `10–20%`，与眨眼混合 |
| 瞳孔反应 | `ParamPupilScale` | 仅做低幅光照/情绪变化，不随鼠标距离乱缩放 |
| 高光视差 | `ParamEyeHighlightX/Y` | 位移小于虹膜，左右光源一致 |
| 目光权重 | `ParamGazeWeight` | `0..1`，由状态所有权平滑切换 |
| 头部补偿 | `ParamEyeHeadCompX/Y` | 头开始跟随时短暂反向补偿 |

精确范围必须在眼眶九点测试后收紧，不能因为参数标称为 `-1..1` 就允许跑满整个纹理区域。

#### X6.3 眨眼

- 默认间隔使用有界非均匀分布，初始约 `2.5–6.5 s`，禁止固定周期。
- 闭合 `60–90 ms`，闭眼停留 `20–70 ms`，睁开 `100–160 ms`。
- 上眼睑承担主要闭合行程，下眼睑只做较小上提；眼角位置稳定，禁止把整只眼压扁。
- 左右眼允许约 `10–25 ms` 的微小错时；除明确表情外不得随机单眼眨。
- 偶发双眨必须有冷却时间，不能形成重复节拍。
- 眨眼只覆盖可见开合，不清零目光位置、速度或当前目标。

#### X6.4 目光与眼—头协同

- 离散目标切换使用 `80–180 ms` 扫视；慢速指针使用 `120–220 ms` 平滑追踪并限制角速度。
- 注视期间只允许低幅漂移和少量微校正，禁止逐帧随机抖动。
- 眼球先到；头部延迟约 `120–280 ms`，承担超出眼眶安全椭圆后的约 `20–35%` 目标量；身体再延迟，最多承担约 `5–12%`。
- 指针只有进入小橘或登录控件关注区后才拥有目光，禁止隔着整个窗口持续吸住眼睛。
- 双眼共享目标；近距离才允许不超过 `0.08` 的轻微会聚，任何时候不得形成斗鸡眼。
- 头部开始跟随时加入短暂反向眼球补偿，使视线不会立即从目标上滑走。

#### X6.5 登录状态眼部规则

| 状态 | 目标与行为 |
| --- | --- |
| `idle` | 在少量安全观察点间扫视，注视约 `0.8–2.8 s`，保留自然眨眼和低幅漂移 |
| `email focus` | 眼球先扫到输入框，头部随后小幅跟随；打字时不冻结，偶尔短暂回看用户方向 |
| `password cover enter` | 停止生成新目标；眼睛回中或轻微下看；闭眼领先爪部接触约 `40–100 ms` |
| `password cover hold` | 保留内部眨眼计时，但可见目光权重降为零；爪下眼睛不得继续追踪指针 |
| `password cover exit` | 爪离开眼眶安全区后才睁眼；保留当前速度，平滑重新捕获有效目标，不先跳回中心 |

目标所有权变化只改变目标与权重，不重置参数。密码状态被中断时，也必须从当前眼睑开合和爪部进度连续退出。

### X7：弹性与微动作

- 耳尖：头部角速度输入，快速、低幅、短收敛；
- 尾巴：尾根主动，尾中/尾尖逐级滞后；
- 胡须和脸颊毛：头脸速度输入，根部稳定；
- 胸腹：呼吸错相，禁止全身缩放；
- 身体回稳：动作速度输入，后躯和接触点保持稳定；
- 眨眼与目光：独立调度；眨眼、扫视、平滑追踪、眼睑跟随、会聚和头部补偿不得互相覆盖；遮眼期间遵守可见性与重新捕获规则。

每条弹性链填写输入、Physics 组、输出参数、驱动 Deformer、刚度、阻尼、限幅和收敛时间，并交付冲击—回稳录像。

### X8：双 Root / 双模型架构试片

用最小替身资产验证两案：

1. 一个 Cubism 包、`XiaojuRoot` 与 `PlanetRoot` 两个独立 Root；
2. 小橘与星球独立模型，运行时按 `PlanetBack -> Xiaoju -> PlanetFront` 组合渲染。

比较遮挡正确性、参数同步、Clipping、Physics、包体、性能和复用性。没有运行时证据前不锁定方案。

### X9：运行时与发布 QA

网页只能驱动参数和模型级渲染顺序。不得重新引入姿态图片、前肢 DOM PNG 或 CSS 关节动画。

证据必须包含：ArtMesh 线框极值、节点级联、41 点遮眼往返、60 秒 idle、九点目光、眼眶极值 Clipping、眨眼五阶段慢放、单双眨、扫视与平滑追踪、头部跟随补偿、目标丢失、三种登录状态中断、弹性回稳、星球接触、Cubism 与目标 WebView 对照，以及构建和目标设备验证。

## 5. 审批 Gate

- `X1 Gate`：三视图统一身体通过后才进入 X2。
- `X2 Gate`：支撑、遮眼块面、物理力矩和控制力矩通过后，只授权 X3 生成完整连续大字型/展开三视图母版。
- `X3 Gate`：完整连续大字型/展开母版通过后才授权 X4 生成细致分层图片。
- `X4 Gate`：隐藏结构、Rest 重组、独立层证据和真实图层边界通过后，才授权 X5 进行三角剖分、ArtMesh 点集和 Layer-Mesh-Node 合同。
- `X5-X7 Gate`：三角网格、节点父子级联、主动 Motion 和弹性顶点分别验收，不能用后一阶段掩盖前一阶段失败。
- `X8 Gate`：运行时试片决定文件边界。
- `X9 Gate`：目标 WebView 的视觉证据决定是否发布。

## 6. 当前状态与下一步

当前权威门禁状态以 `live2d/blueprints/v2-artifact-disposition.json` 为准：`X1` 至 `X5` 已逐 Gate 获得用户继续许可，用户以“可以了，继续下一步吧”通过整个 X5 并授权 X6。X6 已先用 113 个从完整源图裁出的透明遮罩层验证静止重建，再生成参数、Action Tracer 与 keyform 候选；该证据不等同于 63 个精细独立素材已经完成身体空间定位和生产级装配。`X6` 通过前，不进入 X7 Physics、PSD/Cubism 或运行时。

下一步只能围绕 X6 候选做展示、审核与必要修正。若用户明确批准 X6，才进入 X7；在此之前不得把 X5 的弹性权重升级为 Physics 或微动作曲线。
