# Live2D 宠物制作 Skill 蓝图 PRD：小橘试点

> 状态：历史蓝图（M0 与原 Gate 2 已通过）。Gate 3 暴露了缺失的生物力学前置门禁，后续以 `XIAOJU-LIVE2D-V2-RECOVERY-PRD.md` 为当前执行依据；本文不再单独授权进入制作。

## 1. 背景与问题

登录页希望让小橘在 `idle`、邮箱聚焦和密码遮眼之间连续、自然地变化。前几轮实验把问题简化成了“大身体图层 + 两条前肢”，随后又混入整张姿态图和 CSS 图层变换，造成以下问题：

- 图层名称与实际内容不一致，出现整只猫重复叠加、重影和多余爪子。
- 前肢没有肩、肘、腕的父子关节，只能像贴纸一样整体旋转或伸缩。
- 身体、头、耳朵、尾巴和毛发没有完整 Rig，缺少整体生命感。
- 动作没有重心、惯性、回弹和接触约束。
- 当前网页仍是 Live2D Core 与独立 PNG 前肢混合渲染，不能作为正式方案。
- 当前自定义 Core 渲染器没有执行 `.physics3.json`，即使 Cubism 导出 Physics，运行时也不会自动得到物理效果。

本 PRD 设计一个可复用的 `rig-live2d-pet` Skill/工作流，并用小橘登录场景作为第一个试点。先把“如何做对”固定下来，再进入任何模型制作。

## 2. 目标

### 2.1 Skill 目标

建立一条可重复、可审计、可止损的 Live2D 宠物制作流程，覆盖：

1. 原画与现有模型审计。
2. 素材拆分蓝图。
3. 隐藏区域补画与载入 PSD。
4. ArtMesh、Deformer、参数和关键形态设计。
5. 关节层级、惯性与 Physics 设计。
6. Cubism 导出、运行时接入和可视化 QA。
7. 失败时回退，不用临时图片切换掩盖模型问题。

### 2.2 小橘试点目标

- 小橘和星球都拥有独立的逻辑 Rig。
- 小橘按完整角色拆分，而不是只拆当前画面可见区域；躯干、四肢连接、耳根、颈部、胸腹和尾根等被遮挡结构都必须补全。
- 小橘的身体、头、脸、耳朵、眼睛、尾巴、左右前肢均可连续变形。
- 密码遮眼由肩、肘、腕和爪的层级运动完成。
- 动作全过程始终只有两只爪，不重影、不换整图、不出现断肢。
- 邮箱聚焦使用眼球、头部和耳朵的轻量跟随。
- 待机状态有呼吸、眨眼、尾巴和耳尖的低幅次级运动。
- 星球具备独立的漂浮、微旋转、视差和前景遮挡能力。
- 网页只驱动 Live2D 参数，不直接移动解剖部件 PNG。

### 2.3 完整拆分原则

最终模型必须以“一只结构完整的小橘”为素材基础，而不是以登录画面的可见像素为边界：

- 当前被头部、前肢或星球遮住的身体区域，需要依据三视图、毛色走向和猫科解剖进行补画。
- 当前贴在星球后的肩部、胸腹和前肢根部，也要拥有能够独立展开的连续纹理。
- 三视图已经提供完整坐姿依据，因此后躯、腹部、左右后腿、后爪和尾巴也纳入正式底模；它们在登录构图中可以被星球遮住，但不能从素材和节点树中删除。
- 物理、力矩和 Deformer 只负责决定部件如何运动，不能生成缺失纹理；缺失区域必须在建模前补齐。
- Draw Order 和 Clipping 负责在默认姿态重新覆盖补画区域，使 Rest 画面仍与原图一致。
- 动作展开时，完整隐藏结构按父子节点和关节约束自然显露，而不是切换另一张整图。

## 3. 非目标

- 本阶段不创建正式 Skill 目录。
- 本阶段不修改 `.cmo3`、`.moc3` 或纹理图集。
- 本阶段不修改 React、CSS 或自定义渲染器。
- 不重写扫描线光栅化、Delaunay 三角剖分或 Cubism Core。
- 不把登录场景一次扩展为完整桌宠所有动作。
- 不承诺从单张图自动恢复所有被遮挡区域；补画必须经过视觉验收。

### 4.2 当前运行模型缺口

现有 `xiaoju-planet-login.cdi3.json` 只有通用头部、眼睛、嘴、身体和呼吸参数，没有：

- 左右肩、肘、腕参数。
- `ParamPawCover` 的正式关键形态。
- 耳朵与尾巴参数。
- 星球参数。
- Parts/Deformer 层级描述。
- 可执行的 Physics 运行链路。

因此现有运行模型不能通过“再调几个参数”升级为目标效果，必须从素材拆分与 Rig 结构重做。

## 5. 文章原则到 Cubism 的映射

《Live2D动画引擎的图形学原理及实现》中与本项目直接相关的原则：

| 文章概念 | Cubism 对应物 | 小橘中的应用 |
| --- | --- | --- |
| 每个图层绑定网格 | ArtMesh | 每个可独立运动部件独立 ArtMesh |
| 每层一个关键节点 | Rotation/Warp Deformer | 肩、肘、腕、耳根、尾根等支点 |
| 父变换传递给子节点 | Deformer 父子层级 | 身体带动头，肩带动前臂和爪 |
| 矩阵级联 | 层级 Deformer 计算 | Root → Body → Joint → Mesh |
| 弹性节点 | Cubism Physics/摆锤与辅助参数 | 耳尖、尾巴、胸毛、脸颊毛 |
| Action Tracer | 网页状态到参数目标值 | 指针、邮箱聚焦、密码聚焦 |
| 画家算法/图层深度 | Draw Order、Parts、Clipping | 猫身体、星球和爪子的前后遮挡 |

低层光栅化和网格三角剖分由 Cubism/Core 处理，不在 Skill 中重复实现。

## 6. 拟创建的 Skill

### 6.1 名称与触发范围

- 名称：`rig-live2d-pet`
- 默认安装位置：`~/.codex/skills/rig-live2d-pet/`
- 触发场景：用户要求创建、修复、拆层、绑定、导出或验证 Live2D 宠物；用户反馈动画生硬、重影、断层、关节不自然；需要把角色图转换为 Cubism 模型。
- 与 `hatch-pet` 的边界：`hatch-pet` 负责精灵图/图集宠物；`rig-live2d-pet` 负责连续网格变形、Deformer、参数与 Physics，不把两条管线混用。


### 6.3 Skill 自由度设计

- **低自由度**：路径约束、文件命名、alpha 审计、重复图层检测、PSD 格式、导出清单、测试命令。
- **中自由度**：部件命名、网格密度、关键形态数量、参数曲线和 Physics 预设。
- **高自由度**：美术补画、角色风格、动作性格和具体姿态审美。

## 7. 标准工作流与阶段门禁

任何阶段未通过，不得进入下一阶段。

### Gate 0：任务冻结与授权

产物：目标动作清单、主参考图、禁止事项和文件边界。

通过条件：

- 用户确认使用 Live2D 连续变形，而非整图切帧。
- 明确当前只做蓝图、试制或正式交付中的哪一阶段。
- 保留旧运行模型，直到新模型完成可视化验收。

### Gate 1：输入资产审计

产物：文件清单、尺寸、色彩模式、透明度、alpha 包围盒、重复内容报告。

通过条件：

- 每个候选层的真实内容与名称一致。
- 识别整图伪装成部件层、重复猫身、重复爪子和不透明背景。
- 指定唯一的身份参考与唯一的场景构图参考。

失败即停止：不得根据文件名猜测图层内容。

### Gate 2：素材拆分蓝图

产物：带编号的原图标注、图层表、隐藏区域补画表、Draw Order 表、节点树。

通过条件：

- 拆分范围覆盖完整小橘和完整星球，不以当前可见轮廓为终点。
- 每个大幅运动部件独立；身体、头部、耳朵、尾巴和左右前肢都拥有连续结构。
- 每个被遮挡区域都有补画责任归属、参考来源和显露姿态验收图。
- 左右前肢从肩到爪完整，且各自只有一套视觉素材。
- 用户批准蓝图。

### Gate 3：素材拆分与补画

产物：编辑 PSD、载入 PSD、逐层透明 PNG、合成 QA 图。

通过条件：

- 编辑 PSD 保留蒙版和可修改结构。
- 载入 PSD 每个最终部件为一个合并层，RGB 8bit、sRGB、唯一层名。
- 所有连接处有足够纹理延伸，不露透明洞或硬切边。
- Rest 合成图必须像原图；将头、耳、尾、双前肢和星球前景分别移开时，隐藏区展开图必须完整。
- 任何部位不得仅依靠默认遮挡掩盖缺图；Physics 开启后也不能暴露空洞、复制毛纹或接缝。

### Gate 4：ArtMesh 与 Deformer 骨架

产物：基础 `.cmo3`、ArtMesh 接触表、Deformer 树截图。

通过条件：

- 脸、眼皮、耳朵、关节和毛发使用适合形变的网格。
- 大角度关节使用 Rotation Deformer，不直接线性扭曲整个 ArtMesh。
- 子 ArtMesh 不超出父 Warp Deformer 的有效范围。
- 根、身体、头、肩、肘、腕、尾巴层级正确。

### Gate 5：基础参数与关键形态

产物：参数表、关键形态截图、参数往返预览。

通过条件：

- 所有参数在最小值、默认值、最大值均有视觉证据。
- 大动作至少设置必要的中间关键形态。
- 参数正向和反向播放走同一路径，不跳变、不缩短。

### Gate 6：动作与力矩感

产物：动作曲线、关节角度表、接触约束和预览 GIF/视频。

通过条件：

- 主动动作由关节目标角驱动，不让 Physics 决定核心姿态。
- 肩先、肘后、腕与爪最后到位。
- 爪接触眼睛后保持稳定，不穿脸、不漂移。
- 身体有与抬爪相反方向的轻微重心补偿。

### Gate 7：Physics

产物：`.physics3.json`、Physics 分组表、60 FPS 预览。

通过条件：

- Physics 只用于耳尖、尾巴、胸毛和轻微余动。
- 主动关节不会被 Physics 拉离接触点。
- 输出影响度合计不超过 100%。
- 运行时确实执行 Physics，而非仅导出文件。

### Gate 8：导出与运行时接入

产物：`.moc3`、`.model3.json`、纹理、`.physics3.json`、参数绑定代码。

通过条件：

- 网页只设置参数目标值。
- 不加载姿态序列图或解剖部件 PNG 覆盖层。
- 运行时支持 Cubism Physics；若继续使用自定义 Core 渲染器，必须补齐 Framework/Physics 求值与遮罩支持。
- 模型资源全部位于宠物包内，路径相对且可移植。

### Gate 9：可视化 QA 与发布

产物：Rest、25%、50%、75%、Cover、反向恢复的截图/视频，自动检查报告。

通过条件：

- 每帧始终只有两只爪。
- 无重影、透明缝、纹理拉伸、断肢、穿模和突然跳变。
- 低速播放仍自然。
- 状态切换连续可逆。
- 目标设备稳定渲染；测试和构建通过。

## 8. 小橘试点的模型边界

### 8.1 实现选择

使用一个场景级 Cubism 模型 `xiaoju-planet-login-v4`，内部包含两个独立逻辑根：

```text
Scene_Root
├─ Planet_Rig
└─ Xiaoju_Rig
```

不建议立即使用两个完全独立的 `.moc3`，因为猫身体、星球和爪子需要交错 Draw Order。一个模型中的两个逻辑 Rig 可以独立参数化，同时保留跨对象遮挡。

### 8.2 建议 Draw Order

从后到前：

1. `BG_Stars`
2. `Planet_BackGlow`
3. `Xiaoju_Tail`
4. `Xiaoju_Body`
5. `Xiaoju_Head`
6. `Planet_Base`
7. 静止状态下被星球遮挡的前肢根部
8. 抬起后的左右前肢与爪
9. `Planet_FrontRim` 与局部接触遮挡
10. 高光、脸部细节和必要的前景毛发

Draw Order 变化应尽量少；优先用合理拆层和 Clipping 解决，不用重复两套爪子素材。


### 9.6 完整小橘 Deformer 树

正式底模必须先建立完整角色层级，再让登录动作只驱动其中一部分。建议骨架如下：

```text
Xiaoju_Root
└─ Xiaoju_Global_Warp
   ├─ Body_Root
   │  ├─ Chest_Warp
   │  │  ├─ Chest_Fur_Warp
   │  │  ├─ Foreleg_Rig_L
   │  │  └─ Foreleg_Rig_R
   │  ├─ Belly_Warp
   │  ├─ RearBody_Warp
   │  │  ├─ Hip_Rotation_L
   │  │  │  └─ HindLeg_Warp_L
   │  │  │     └─ HindPaw_Warp_L
   │  │  ├─ Hip_Rotation_R
   │  │  │  └─ HindLeg_Warp_R
   │  │  │     └─ HindPaw_Warp_R
   │  │  └─ Tail_Root_Rotation
   │  │     └─ Tail_01..Tail_Tip
   │  └─ Neck_Warp
   │     └─ Head_Rotation
   │        ├─ Face_Warp
   │        │  ├─ Eye_Rig_L
   │        │  ├─ Eye_Rig_R
   │        │  ├─ Muzzle_Warp
   │        │  └─ Mouth_Warp
   │        ├─ Ear_Rig_L
   │        └─ Ear_Rig_R
   └─ Contact_Shadow_Warp
```

约束：

- `Xiaoju_Global_Warp` 只处理整猫的重心、呼吸和轻微视差，不替代局部关节。
- 前腿从胸肩生长，后腿和尾巴从后躯生长；禁止把四肢或尾巴直接挂在全局节点下。
- 默认被星球挡住的腹部、后腿和尾根仍参与父节点运动，不能冻结为不可用的占位层。
- Deformer 父子树负责运动传递，Draw Order 负责前后遮挡，两者不能互相替代。
- 登录动作没有显露某个隐藏部件时，也要用展开测试验证该部件随身体、髋部或尾根运动正确。

## 11. 力矩、关节与动作曲线

### 11.1 设计模型

主动关节采用目标角与层级变换；次级部位采用弹簧阻尼思想：

```text
torque = stiffness × (targetAngle - angle) - damping × angularVelocity
angularAcceleration = torque / inertia
```

Cubism 中不必实现完整刚体求解器，但需要用以下手段保留物理意义：

- Rotation Deformer 放在真实肩、肘、腕支点。
- 各段长度固定，避免用 `scaleY` 伪装抬臂。
- 爪尖轨迹由父子关节角度共同产生。
- 身体以反方向小幅转动补偿抬起双臂的视觉重心。
- 接触阶段锁定爪心位置，只允许微小压缩和毛发余动。

### 11.2 遮眼动作时序建议

总时长初始目标：抬起 800–950 ms，放下 700–850 ms。

| 阶段 | 进度 | 行为 |
| --- | ---: | --- |
| 准备 | 0.00–0.12 | 目光停止跟随，身体略下沉，耳朵轻收 |
| 肩启动 | 0.08–0.38 | 肩部先转，上臂离开星球 |
| 肘跟随 | 0.22–0.62 | 肘部屈曲，前臂沿脸侧上升 |
| 腕部对准 | 0.48–0.82 | 腕部微调，左右爪错开 60–100 ms |
| 接触 | 0.78–0.94 | 爪心落到眼眶区域，眼睛闭合 |
| 稳定 | 0.94–1.00 | 轻微压缩与一次小幅收敛，不持续晃动 |

左右动作略不对称，但终点必须自然覆盖双眼。

## 12. 微动作与 Physics 蓝图

### 12.1 微动作调度器

微动作不是一条重复播放的 `idle` Motion，而是多个独立通道经过优先级、权重和阻尼混合后的结果。

| 通道 | 建议节奏 | 动作特征 | 状态规则 |
| --- | --- | --- | --- |
| `Blink` | 间隔约 2.5–6.5 秒，偶发双眨 | 闭合 60–90 ms，短暂停留，张开 100–160 ms；左右眼允许 10–25 ms 偏差 | 密码遮眼期间继续计时但降低可见权重；爪子放下后可自然补一次眨眼 |
| `EyeSaccade` | 1.5–4 秒一次低幅目标变化 | 眼球先到、头部后跟；不持续追逐鼠标 | 邮箱聚焦时转为输入框方向，退出时平滑回到环境观察 |
| `Breath` | 3.2–4.8 秒一周期并轻微漂移 | 胸、腹、鼻翼不同相位，禁止全身等幅缩放 | 所有状态保留；主动动作只降低幅度，不重置相位 |
| `EarAttention` | 单耳 4–12 秒一次 | 左右耳独立，小幅耳根转动叠加耳尖回弹 | 交互时靠近事件方向的一侧先响应，另一侧延迟跟随或不动 |
| `TailIdle` | 4–10 秒一次慢变化 | 尾根主动、尾尖滞后，偶尔停住 | 遮眼和邮箱聚焦时降低幅度，不能与耳朵固定同步 |
| `WhiskerCheek` | 由呼吸、头动和表情触发 | 胡须根稳定，尖端和脸颊毛短暂余动 | 不单独循环；作为头脸运动的次级响应 |
| `BodySettle` | 主动作结束后 0.25–0.6 秒 | 胸腹和后躯轻微回稳，后爪保持接地 | 只响应速度变化，不制造持续摇摆 |

调度规则：

1. 优先级为 `密码遮眼 > 明确交互反应 > 邮箱聚焦 > idle 微动作`，但高优先级动作不得把低优先级通道直接归零。
2. 每个通道保留自己的相位、目标值和速度；状态切换只改变目标与权重，使用连续插值和速度阻尼，禁止参数瞬跳。
3. 眨眼间隔、耳朵选择和尾巴目标使用有限随机分布与冷却时间；不得使用完全相同的固定循环。
4. 呼吸、耳朵、尾巴和眼神不得在同一帧同时到达极值；启动相位必须错开。
5. Motion、用户输入和 Physics 写入同一参数时，必须声明混合方式（Override/Add/Multiply）与权重，禁止最后写入者无条件覆盖。
6. 微动作调度器暂停或恢复时保持当前值与速度，不能跳回 Rest。

### 12.2 目光控制器

目光由“目标选择、眼球到达、眼睑联动、头部跟随、身体补偿”五层组成，不能把鼠标坐标直接写入眼球参数。

#### 目标来源与优先级

```text
密码遮眼接触点
> 明确交互目标（点击、悬停中的控件）
> 当前输入框
> 靠近小橘的指针
> idle 环境观察点
```

- 指针只有进入小橘或登录控件的关注区域后才成为目标，禁止从窗口另一端持续吸住视线。
- 目标坐标先转换为模型局部空间，再限制在眼眶安全椭圆内；超出范围的剩余角度交给头部承担。
- 目标源切换时保留当前眼球速度，用缓动进入新目标，不先回中心。

#### 运动模式

| 模式 | 建议参数 | 用途 |
| --- | --- | --- |
| 快速扫视 `Saccade` | 80–180 ms 到达；终点可有极小修正 | idle 观察点或离散目标切换 |
| 注视漂移 `FixationDrift` | 幅度 0.02–0.06；低频、无固定周期 | 避免长时间注视像冻结贴图 |
| 平滑追踪 `SmoothPursuit` | 输入平滑 120–220 ms，并限制最大角速度 | 跟随关注区域内缓慢移动的指针 |
| 眼—头协同 `EyeHeadLead` | 眼球先行；头延迟 120–280 ms，承担约 20–35% 目标量 | 让观察动作具有注意力和重量感 |
| 身体补偿 `BodyFollow` | 再延迟 180–350 ms，承担约 5–12% | 仅用于较远目标，保持后爪接地 |

#### 双眼、眼睑与高光约束

- 双眼通常共享 `ParamEyeBallX/Y`，保持同向；只有近距离目标使用不超过 0.08 的轻微会聚，禁止斗鸡眼。
- 上下看时，眼睑以眼球纵向位移的约 10–20% 跟随，防止虹膜穿出眼眶；该跟随不能覆盖眨眼闭合参数。
- 左右眼允许极小到达时间差，但目标方向不得相反。
- 眼睛高光随眼球移动的比例应小于虹膜，保持光源一致感；不能将高光完全焊死在瞳孔中心。
- 头部转动时加入低幅反向眼球补偿，使视线在头开始跟随的瞬间仍锁定目标。

#### 登录状态行为

- `idle`：在安全椭圆内选择少量环境观察点，注视 0.8–2.8 秒，穿插微漂移和自然眨眼；不持续看向随机噪声。
- `email focus`：先扫视到输入框，再由头部小幅跟随；打字期间保留微漂移，偶尔短暂看向用户方向后返回。
- `password cover enter`：停止产生新目标，眼睛轻微回中或下看，闭眼先于爪子接触 40–100 ms。
- `password cover hold`：保留内部眨眼计时但不驱动可见眼球追踪，避免爪下眼睛仍四处移动。
- `password cover exit`：爪子离开眼眶安全区后再睁眼，随后重新捕获当前有效目标，不能在被遮挡时突然跳向新坐标。

### 12.3 Physics 分组

| Physics 组 | 输入 | 输出 | 级数 | 性格 |
| --- | --- | --- | ---: | --- |
| `Ear_L/R_Physics` | 头部 X/Z、身体 Z | 耳尖参数 | 1–2 | 快速、低幅、快速收敛 |
| `Tail_Physics` | 身体 X/Z、拖动速度 | 尾巴 01–03 | 3 | 慢、柔软、明显滞后 |
| `BodyMass_Physics` | 身体 X/Y/Z、动作速度 | 腹部、后躯与髋部余动 | 1–2 | 重、低幅，不改变承重点 |
| `HindPaw_Load_Physics` | 髋部位移、身体压缩 | 后腿与后爪承重形变 | 1 | 极低幅，保持坐姿接地 |
| `ChestFur_Physics` | 呼吸、身体 Y | 胸毛摆动 | 1 | 极低幅 |
| `CheekFur_Physics` | 头部 X、身体 Z | 脸颊毛 | 1 | 极低幅、短余动 |
| `Whisker_Physics` | 头部 X/Z、口鼻形变 | 胡须尖端 | 1–2 | 根部稳定、尖端快速低幅收敛 |
| `PawSettle_Physics` | 遮眼速度 | 腕部余动 | 1 | 只在接触前收敛，接触后限制输出 |

运行目标为 60 FPS。若 Physics 输出总影响度超过 100% 或造成爪子离开眼睛，则不通过 Gate 7。

## 13. 运行时架构要求

当前 `live2dCoreRenderer.ts` 只直接调用 Cubism Core；Core 负责模型计算和 Drawable 数据，但不会替应用执行完整的 Cubism Framework Physics/Motion 管线。

正式方案必须二选一：

1. 接入官方 Cubism SDK for Web Framework，使用其 Motion、Physics、Pose 与 Clipping 管线；或
2. 保留自定义渲染器，但实现并验证 `.physics3.json` 求值、Motion 曲线、遮罩、Draw Order 和参数混合。

试点优先选择方案 1，以减少重复实现引擎底层的风险。只有在包体、许可或框架冲突明确不允许时，才评估方案 2。

## 15. 停止条件

遇到以下任一情况必须停止并回到上一 Gate：

- 图层实际内容与名称不符。
- 一个“部件层”包含完整角色或另一只爪。
- 隐藏区域没有补画，只能依靠遮挡掩盖。
- 中间姿态出现透明缝、穿脸或关节缩短。
- 目光直接绑定原始指针坐标，出现抖动、跳回中心、双眼方向冲突或虹膜穿出眼眶。
- 为了修视觉问题重新引入整图切换、CSS 解剖动画或重复爪子。
- Cubism 内看似正常，但导出运行时不执行 Physics/遮罩。
- 没有用户审核就从蓝图阶段进入制作阶段。
