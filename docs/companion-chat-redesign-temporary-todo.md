# 陪伴聊天形态整改临时 TODO

日期：2026-08-11
状态：临时执行清单，整改完成并经用户验收后删除或合并进正式设计文档。Companion Harness 由独立的 `docs/companion-harness-todo.md` 管理，已推进到 Phase 8 的纯逻辑与自动化门；这不关闭本文未完成的 UI、Tauri 或视觉门。
当前总进度：`2 / 6 阶段（约 33%）`；整改代码进度：`1 / 5 阶段（20%）`

## 1. 目标

把平台内聊天从“传统网页聊天 + 房间/页面切换”整改为真正围绕桌宠的陪伴体验：

- 桌面宠物旁的气泡聊天继续作为轻量入口。
- 平台内只有一个主动聊天形态：陪伴房。
- 传统网页式消息列表降级为只读的“本次陪伴记录”，不再是可输入、可发送的第二种聊天模式。
- 用户感知为“和同一只宠物持续相处”，Provider 上下文仍保持有界、分段、隐私安全。
- 宠物是房间视觉与回应的主体，不把普通聊天网页换一张背景就称为陪伴房。

## 2. 边界

本 TODO 只负责陪伴聊天的信息架构、界面、状态衔接和相关回归验证。

明确不做：

- 不实现或调整 Harness；`docs/companion-harness-todo.md` 由独立路线负责，当前 Harness Phase 8 的状态、观测和发布门禁不在本文内重复关闭。
- 不扩展、重写或限定具体 Provider；只消费现有 Provider 中立状态。
- 不改 API Key、Endpoint、模型接入或远程请求协议。
- 不新增完整聊天记录持久化、云同步、自动总结或“最近会话”侧栏。
- 不修改 Memory、Soul、偏好和任务抽取的数据合同，除非只是修复本阶段造成的回归。
- 不重做桌面气泡聊天，不改变右键双击、左键停止/撤回、Esc、空白处退出和 90 秒空闲退出的既有语义。
- 不硬编码宠物 id、宠物资源路径、spritesheet 尺寸或单一宠物特例。
