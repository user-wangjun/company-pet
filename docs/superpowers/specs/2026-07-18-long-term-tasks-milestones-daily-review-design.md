## 3. 产品目标

任务时间模型分为三层：

1. 普通任务：默认属于某一天，默认日期为创建当天。
2. 长期任务：拥有开始日期和截止日期，在整个周期结束时结算。
3. 日期节点：属于某个长期任务，在指定日期或指定时刻作为一项可执行任务出现。

核心原则：

- 长期任务本体不应每天被视为“未完成”。
- 节点是可以独立完成、提醒、延期和统计的真实执行项。
- 今日回顾只评价今天明确需要处理的内容。
- 桌宠负责陪伴和鼓励，不在回顾环节批评用户。

## 4. 任务类型与时间规则

### 4.1 普通任务

- 新建任务时日期默认设为当天。
- 用户可以选择其他日期，也可以选择具体时间。
- 普通任务在指定日期进入“今天”。
- 如果指定了具体时间，则按时间排序，并可以配置提醒。
- 原有 `includeToday` 能力继续兼容；它表示用户主动将任务加入今天。

### 4.2 长期任务

- 用户切换为“长期任务”后设置开始日期和截止日期。
- 长期任务本体在周期进行中只显示“进行中”，不参与每天的完成率。
- 长期任务提前完成时，记录实际完成日期，并将整个周期判定为完成。
- 截止日期结束仍未完成时，长期任务在周期层面判定为未完成，但不反复拖低之后每天的完成率。
- 没有截止日期时视为持续任务，不计算周期完成率，只展示节点进度。
- 没有节点的长期任务在周期内只展示进行状态，到截止日再结算一次。

### 4.3 日期节点

- 每个节点必须有标题和日期。
- 节点可以只选日期，也可以进一步选择具体时间。
- 只选日期时，它是全天节点。
- 选择具体时间时，它按当天时间排序，并可以设置独立提醒。
- 节点到达指定日期后自动进入当天任务列表。
- 节点在当天列表中显示所属长期任务，例如“完成初稿 · 来自：毕业论文”。
- 在当天列表或长期任务详情中完成节点，两个位置必须同步。
- 节点完成会更新长期任务的节点进度。
- 节点当天未完成，之后进入逾期列表，但只影响原定日期的完成率一次。
- 节点可以提前完成；它计入实际完成当天的成果，原节点日期不再出现。
- 所有节点完成后提示用户是否完成长期任务，不强制自动完成，因为可能还有未节点化的收尾工作。

### 4.4 精确时间与提醒

节点支持两种精度：

- 日期：`YYYY-MM-DD`，作为全天节点。
- 日期时间：`YYYY-MM-DD HH:mm`，作为定时节点。

定时节点可以复用现有提醒能力，支持：

- 到点提醒。
- 提前 10 分钟、30 分钟、1 小时或1天提醒。
- 延后提醒。
- 桌宠气泡和系统通知。

提醒触发只针对该节点，不改变长期任务本体的周期。

## 5. 推荐数据模型

推荐把节点实现为一等 `Task` 记录，而不是仅作为长期任务内的嵌套 JSON。这样节点可以直接复用现有提醒、提醒实例、完成历史、逾期、延期、回收站和查询逻辑。

建议扩展：

```ts
export type TaskKind = "single" | "long_term" | "milestone";
export type SchedulePrecision = "date" | "datetime";

export type Task = {
  // 保留现有字段
  id: string;
  title: string;
  status: TaskStatus;
  dueAt: string | null;

  // 新增字段
  kind: TaskKind;
  parentTaskId: string | null;
  startAt: string | null;
  schedulePrecision: SchedulePrecision;
};
```

字段含义：

- `single`：普通任务。
- `long_term`：长期任务本体。
- `milestone`：长期任务的日期节点。
- `parentTaskId`：节点所属长期任务；普通任务和长期任务本体为 `null`。
- `startAt`：长期任务开始时间；普通任务和节点通常为 `null`。
- `dueAt`：普通任务日期、长期任务截止日期或节点日期。
- `schedulePrecision`：区分全天日期与具体时刻，避免界面误显示时间。

实现时可以根据现有日期工具选择 ISO 字符串或本地日期字段，但必须满足：

- 日期节点不会因为 UTC 转换跨天。
- 夏令时或时区设置变化后，全天节点仍留在用户选择的本地日期。
- 具体时间节点仍能生成稳定的提醒时间。

若继续使用 ISO 存储全天日期，必须增加明确的本地日期归一化函数和测试；不得在组件中零散拼接日期字符串。

### 5.1 数据库迁移

将数据库升级到新的 schema 版本，迁移原则：

- 所有旧任务迁移为 `kind: "single"`。
- 旧任务的 `parentTaskId` 和 `startAt` 为 `null`。
- 旧任务根据现有 `dueAt` 初始化时间精度；无法可靠判断时使用 `datetime`，以保持原行为。
- 旧提醒、提醒实例、历史和回收站记录保持关联关系。
- 迁移必须幂等，多次加载不能重复创建节点或历史记录。
- 无效的 `parentTaskId` 应降级为普通任务并记录可诊断警告，不能让整个数据库加载失败。

### 5.2 删除与恢复

- 删除长期任务时，界面必须明确说明其节点会一并进入回收站。
- 恢复长期任务时一并恢复仍存在的节点。
- 单独删除节点不删除长期任务。
- 永久删除长期任务时清理其节点及相关提醒实例，遵守现有回收站策略。

## 6. 今日列表与查询规则

当天执行项包括：

```text
今日执行项 =
  日期为今天的普通任务
  + 日期为今天的节点
  + 今天触发的重复任务实例
  + 用户主动加入今天的任务
```

不应自动进入今日执行项：

- 周期仍在进行中的长期任务本体。
- 截止日期在未来且未加入今天的普通任务。
- 日期不在今天的未来节点。
- 仅因为历史上已过期而遗留的任务。

长期任务应在今日界面使用独立的紧凑进度区域展示，例如：

```text
毕业论文
3 / 5 个节点已完成 · 还剩 12 天
```

这个进度区域不参与今日完成率。

## 7. 今日回顾三档规则

用户已确认只保留三个档位，以“一半”和“零”为边界。

### 7.1 今日统计集合

参与统计的是今天明确需要处理的执行项，而不是任务库中的所有任务。

统计集合应按任务或节点 ID 去重，由以下内容组成：

- 原定日期为今天的普通任务和节点。
- 今天触发的重复任务实例。
- 今天主动加入“今天”的任务。
- 今天实际完成的任务或节点，包括提前完成的未来任务和完成的历史逾期任务。
- 今天从今日执行项延期出去的任务或节点。

以下内容不进入分母：

- 长期任务本体。
- 取消的任务或节点。
- 没有在今天被处理的历史逾期任务。
- 尚未到日期且今天也没有完成的未来任务或节点。

同一任务当天多次延期只在分母中计算一次，延期次数仍可作为独立统计展示。

### 7.2 完成率

```text
完成率 = 今日完成执行项数 / 今日有效执行项总数
```

三档判定：

- `at_least_half`：完成率大于或等于 50%，刚好一半归入这一档。
- `below_half`：完成率大于 0% 且小于 50%。
- `zero`：完成数为 0；今日完全没有任务时也归入这一档。

当分母为 0 时，完成率展示为“暂无今日任务”，不能显示 `0 / 0` 或 `NaN`。逻辑状态仍使用 `zero`，方便只保留三组宠物反馈。

### 7.3 长期任务周期结果

长期任务结果与每日完成率分开：

- 周期进行中：展示节点进度，不判定每日成功或失败。
- 周期内完成：记录一项周期成果，可在完成当天的回顾中单独展示。
- 周期结束未完成：记录一次周期未完成，可在截止日回顾中单独展示。
- 长期任务本体无论成功或未完成，都不加入普通任务的每日完成率分母。

## 8. 桌宠回顾文案

回顾发言者始终是当前激活的桌宠，不根据历史使用时长切换宠物。

当前四个宠物包的 `dailyReview` 文案已更新，它们应作为 `at_least_half` 档的现有庆祝文案：

- 小橘：`哇哦，今天完成了这些事情，明天是不是可以给小橘买更多鱼鱼呀！`
- IKUN：`叽！IKUN不错呀，继续努力，鸽鸽看好你！`
- DS：`真厉害，我和梁圣都看好你哇！`
- 蒜鸟：`蒜鸟蒜鸟，看到你这么努力我就放心了。`

建议将反馈场景扩展为：

```ts
type TaskFeedbackScene =
  | ExistingScenes
  | "dailyReviewAtLeastHalf"
  | "dailyReviewBelowHalf"
  | "dailyReviewZero";
```

兼容策略：

- 现有 `dailyReview` 作为 `dailyReviewAtLeastHalf` 的向后兼容来源。
- 宠物包缺少新档位时使用平台中性文案。
- 不得在平台代码中根据 `activePetId` 硬编码宠物语气。
- `below_half` 和 `zero` 的四宠物最终文案尚未由用户确认，不应擅自覆盖为正式角色台词。
- `zero` 文案需要同时适配“有任务但一项未完成”和“今天完全没有任务”，避免错误陈述。

平台中性降级文案可暂用：

- `at_least_half`：`今天完成了不少，辛苦了。`
- `below_half`：`今天已经迈出了一步，剩下的我们慢慢来。`
- `zero`：`今天还没有留下完成记录，明天我们从一件小事开始吧。`

回顾是一天的收尾，不是第二次催办。文案不得羞辱、责备或制造焦虑。

## 9. 界面与交互

### 9.1 创建普通任务

- 默认选择“当天任务”。
- 日期默认当天。
- 时间为可选项；不选时间即全天任务。
- 保留现有标题、备注、优先级、项目、附件、提醒和重复规则。

### 9.2 创建长期任务

- 在任务类型控件中选择“长期任务”。
- 显示开始日期和截止日期。
- 开始日期默认当天。
- 截止日期可以为空，表示持续任务。
- 提供“添加节点”操作。

### 9.3 节点编辑

每个节点至少包含：

- 标题。
- 日期。
- 可选具体时间。
- 可选提醒设置。

节点列表按日期时间排序。添加、修改和删除节点不应造成整个任务编辑面板跳动或丢失尚未保存的内容。

### 9.4 长期任务详情

详情应展示：

- 开始日期与截止日期。
- 当前周期状态。
- 已完成节点数与总节点数。
- 节点时间线或紧凑列表。
- 距离截止日的剩余天数。
- 完成长期任务的明确操作。

不要把节点列表做成卡片嵌套卡片；沿用当前工作区的紧凑任务风格。

### 9.5 今日回顾

现有面板继续展示：

- 今日完成数。
- 延期数。
- 取消数。
- 今日剩余数。
- 已完成任务。
- 接下来优先事项。
- 当前桌宠的回顾话语。

新增或调整：

- 展示 `已完成 / 今日有效执行项` 和百分比，分母为 0 时显示“暂无今日任务”。
- 根据三档状态选择当前宠物反馈。
- 长期任务周期成果或进行中进度使用独立区域，不混入每日完成率。
- “明天先看”的数据应明确为下一步焦点，不要把所有未来任务都混成明日到期任务。

## 10. 状态同步与边界行为

- 完成节点后，父长期任务进度立即更新。
- 从长期任务详情完成节点和从今日列表完成节点必须调用同一个 store 操作。
- 完成长期任务不会伪造所有节点的完成历史。
- 用户确认完成长期任务后，未完成的未来节点归档为“不再需要”，不计取消数；如现有状态不足，可新增明确的节点归档原因。
- 修改长期任务周期后，落在新周期外的节点应提示用户处理，不能静默移动或删除。
- 删除或取消长期任务时，必须明确处理节点和提醒。
- 重复任务若作为节点使用会显著增加语义复杂度，第一版建议禁止节点设置重复规则；需要重复执行时创建普通重复任务。
- 一个节点只能属于一个长期任务。
- 父任务不存在或已永久删除时，孤立节点应安全降级或被迁移清理，不能导致查询崩溃。

## 11. 推荐实施顺序

1. 扩展类型并实现 schema 迁移，确保旧数据无损。
2. 为节点增加统一的 store 创建、更新、完成、删除和恢复操作。
3. 更新任务查询，让节点按日期进入今天、即将提醒和逾期列表，并排除长期任务本体。
4. 更新普通任务和长期任务的创建、编辑及详情界面。
5. 将节点提醒接入现有提醒模板、实例、桌宠气泡和系统通知。
6. 重写今日回顾统计为三档完成率，并加入长期任务独立进度。
7. 扩展宠物反馈场景，保留现有 `dailyReview` 兼容行为。
8. 完成单元测试、组件测试、构建和人工视觉回归。

不要在同一步中顺手重构无关模块。优先复用现有 task store、query、history 和 reminder 状态机。

## 12. 测试要求

### 12.1 数据与迁移

- schema v1 旧任务迁移为普通任务且字段、提醒和历史不丢失。
- 迁移幂等。
- 无效父任务引用不会导致数据库无法加载。
- 长期任务及节点删除、恢复、永久清理行为正确。

### 12.2 查询

- 普通任务默认日期为创建当天。
- 全天节点在选择的本地日期进入今天。
- 定时节点在正确日期进入今天，并按时间排序。
- 未来节点不会提前进入今天。
- 周期中的长期任务本体不会进入每日执行项。
- 未完成节点在日期过后进入逾期。
- 重复任务仍只按当前实例参与今日列表。

### 12.3 完成与进度

- 两个入口完成节点时状态同步。
- 节点完成后父任务进度正确。
- 提前完成节点计入实际完成日，原计划日不重复出现。
- 所有节点完成不会自动完成父任务，只产生确认提示。
- 完成父任务不会伪造节点完成历史。

### 12.4 今日回顾

- `1/2` 判定为 `at_least_half`。
- `2/5` 判定为 `below_half`。
- `0/3` 判定为 `zero`。
- `0/0` 判定为 `zero`，界面显示“暂无今日任务”。
- 取消任务不进入分母。
- 同一任务多次延期只进入分母一次。
- 未处理的历史逾期任务不进入今天的分母。
- 今天完成的历史逾期任务进入今天的完成成果。
- 长期任务本体不影响每日完成率。
- 当前宠物切换后，回顾文案随当前宠物切换。

### 12.5 提醒与回归

- 定时节点能创建、触发、延后和完成提醒实例。
- 节点提醒不修改父任务周期。
- 浏览器预览缺少 Tauri API 时不崩溃。
- 原有普通任务、重复任务、关怀提醒和桌宠交互保持正常。

实现完成后至少运行：

```powershell
npm test
npm run build
cd src-tauri
cargo test
cargo check
```

## 13. 验收示例

创建长期任务：

```text
毕业论文
周期：2026-07-01 至 2026-07-30

节点：
2026-07-05          收集资料
2026-07-12 14:00    完成初稿
2026-07-20 18:00    完成修改
2026-07-30 10:30    正式提交
```

预期：

- 7 月 12 日的“今天”列表出现“完成初稿”，并标注来自“毕业论文”。
- 完成该节点后，今日完成数增加 1，长期任务进度同步增加。
- 7 月 13 日不会因为“毕业论文”本体仍未完成而拉低完成率。
- 如果 7 月 12 日节点未完成，它之后进入逾期，但不会在每天的完成率中重复计算。
- 7 月 30 日前完成长期任务，周期结果记为完成；未完成则只在周期层面结算一次。

## 14. 非目标

- 第一版不实现节点依赖关系或关键路径。
- 第一版不实现甘特图。
- 第一版不实现百分比手动填报。
- 第一版不允许节点自身再包含子节点。
- 第一版不让节点设置重复规则。
- 不根据宠物历史使用时长选择回顾发言者。
- 不把宠物专属文案硬编码到平台 `src/` 中。
- 不改变现有宠物素材、动画图集或声音资源。
