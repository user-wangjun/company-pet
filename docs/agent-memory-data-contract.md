# Agent Memory / Soul / Task 正式数据契约

状态：阶段 0/0.1 正式契约（2026-08-03）。本契约描述当前桌面端边界；它不授权云端同步、远程上传或让模型自行修改数据。

第一版范围：当前宠物的轻量陪伴聊天。默认不保存完整原始聊天记录；Gemini、OpenAI 或本地 Provider 可以替换，Memory、Task 和检索契约不随 Provider 重写。长期写入只接受用户明确要求或确认后的低风险内容。

## 统一敏感内容边界

`src/pet-core/companionPrivacy.ts` 是所有用户可控持久化和远程外发入口共用的 fail-closed 规则。以下类别一律视为敏感：密码/口令、Token（含 access/refresh/bearer）、API Key、私钥/SSH Key、身份证件和社会安全号码、银行卡/信用卡/银行账号、精确或完整地址、医疗诊断/病史/医疗记录/用药/处方/治疗，以及这些类别的常见英文表达。

除标签表达外，还识别常见凭据形状：PEM 私钥头、`sk-`/`rk-`/`pk-`、`ghp_`/`github_pat_`、`xox...`、`AIza...`、Bearer Token、JWT，以及格式化 SSN、18 位身份号码和 13--19 位卡号。系统策略文本可以提到这些类别；只有用户可控字段中的类别或已附着值触发安全拒绝。

- 敏感用户内容不得进入 Preference、Memory、Task 事实实体本身（包括标题、备注、项目、证据、来源消息、附件引用和提醒覆盖字段），也不得进入 Outbox 事件或远程请求。
- 领域入口统一安全失败，不把原文截取到错误提示、普通日志、Tombstone、Provider 信息或请求体中；远程历史按整条消息丢弃。
- “敏感”不是把内容自动改写成可保存的事实；拒绝保存后只保留最小的通用反馈。Session 可以在当前窗口短暂显示用户输入，但不因此获得长期保存或远程发送权限。

## 路由与写入流

路由先决定事实类型，再调用对应的领域写入边界；不能因为某句话同时包含“记住”“提醒”或宠物人格语气，就复制到多个事实源。

| 输入 | 唯一持久化结果 |
|---|---|
| `以后叫我阿星`、`以后叫我阿星。` | 仅写全局 Preference `global.nickname`；不创建 Memory，也不保存完整聊天原文。 |
| `我喜欢桂花茶，请记住。`、`请记住我喜欢桂花茶。` | 写全局 `preference` Memory，带结构化 `scope`、`sourceMessageId`、`evidence`、`delete` 语义；不把它复制成 Task。 |
| `明天下午三点提醒我交报告。` | 仅写 Task/Reminder 事实；不创建普通 Memory。 |
| `我可能下个月想学摄影。`、`我今天好累。` | 不写 Task 或 Memory；只留在当前 Session/Provider 的短暂处理范围。 |
| `忘掉刚才那条。` | 调用真实的最近 Preference/Memory 删除边界；有可删数据才确认成功，没有则诚实反馈无可删除项。 |

提醒必须有可解释的事项和时间；模糊愿望不默认成今天的 Task。昵称是 Preference，不是 Memory；“记住”只有在内容属于低风险、可结构化的明确事实时才进入 Memory。

## 一句话判断表

| 数据 | 保存位置 | 谁可见 | 何时过期 | 如何删除 |
|---|---|---|---|---|
| SOUL | `public/pets/<pet-id>/SOUL.md`，宠物包内只读文件 | 当前宠物的 Context/Provider；用户可查看本地包 | 不按时间过期，随宠物包版本变化 | 从宠物包移除 `soulPath`/文件；运行时不写入、不同步 |
| 偏好 | 本机 `localStorage` 的 `yuxin-companion-preferences-v1` | 用户级或 `pet:<id>` 作用域；当前聊天和提醒逻辑可见 | 默认不自动过期，直到用户改写 | 设置入口或“忘掉这个”删除最近一条；不得写入敏感值 |
| Memory | 本机 `yuxin-companion-memory-v1`，含结构化条目和 Tombstone/Outbox 投影 | `global` 或当前 `pet:<id>`；只作为参考上下文 | `expiresAt` 到期、禁用、被替代或用户删除 | 设置入口编辑/禁用/删除；删除保留本地 Tombstone 语义，不回到检索 |
| Session | 运行时 `CompanionChatState`（React state/ref），不写长期存储 | 当前窗口、当前宠物和本次聊天参与者 | 退出、换宠、外部点击，或空闲超过 90 秒 | 退出聊天；停止回复只撤回未完成的用户气泡，不把整段会话转成 Memory |
| Task | 本机 `yuxin.tasks.v1`，Task 是提醒和任务的事实源 | 用户级，所有宠物可表达同一任务；宠物身份只在来源/投递层 | 完成/取消后进入回收站；删除满 30 天可物理清理 | 软删除先写 `deletedAt` 和 delete Event；用户确认后可永久删除 |
| Event | 本机 `yuxin-local-repository-outbox-v1`；安全投影的变更事件 | Repository/未来 Transport 可见；Provider 和普通聊天不可见 | 当前无远端确认，不自动过期；未来需按 ack/cursor 压缩 | 随事实删除产生 delete Event；未来只在确认传播后压缩，不能把 Event 当事实源 |

## 远程 Provider 外发策略（阶段 0.1）

### Provider 分类与启用条件

- **本地 Provider** 只在本机生成回复，不发起网络请求，也不把聊天上下文交给远程服务。
- **远程 Provider** 只有在用户主动配置了远程 API Key 后才启用；它可以发送本轮必要上下文，但请求必须先经过统一的远程上下文过滤器。
- 没有 API Key、API Key 为空或只有空白时，平台固定使用本地 Provider，不会偷偷切换到 Gemini、任何自定义 Gemini endpoint 或其他远程服务。
- API Key 只作为本地连接配置使用；它不进入 Memory、Session、Outbox、普通聊天上下文或日志，也不会出现在用户可见的 Provider 提示中。

当前代码已经把本地 Provider、远程 Provider 的纯工厂、聊天打开时的 `info` 解析、配置变化重解析、远程上下文过滤和远程失败后的本地降级拆开。桌面 App 的实际入口（右键菜单“陪我聊聊”与右键双击快捷方式）不提供远程 Key 配置；没有 OS Secret Store 时不会把 Key 放进 `localStorage`，因此内置 App 当前固定使用本地 Provider。测试中的手动注入 Key 只验证 Provider 合同，不代表远程模式已作为用户配置流程交付。

### 远程模型请求、Repository 持久化与同步边界

- **远程模型请求**：只有用户明确配置 Key 的 Provider 才可能发起；它是一次用户主动聊天发送动作的远程调用，不是同步，也不是本地事实写入。当前内置 App 没有 Key 配置入口，因此实际聊天不发起网络模型请求。
- **Repository 持久化**：Preference、Memory、Task 和本地设置写入本机存储；写入成功才更新 UI，失败不显示成功、不关闭提醒、不清理待处理动作。
- **Outbox / 同步**：Outbox 只是本机的安全变更投影和未来 Transport 边界；当前没有远程发送、云端数据库、ack/cursor、跨设备同步或远程持久化。Outbox 中的事件不会因为聊天 Provider 存在就自动上传。

### 远程请求允许发送的内容

远程 Provider 只接收经过过滤、裁剪后的必要上下文：

- 当前用户输入（当前输入命中敏感规则时不发送请求）；
- 未命中敏感规则的近期安全历史消息；历史中的敏感消息整条删除，不保留原文、局部片段或证据；
- 未命中敏感规则的当前宠物 Soul、平台策略和必要的回复风格提示；Soul 和平台策略不能包含用户隐私；
- 未命中敏感规则、且作用域匹配并仍处于有效状态的 Preference 和已确认 Memory 内容。Memory 的 `evidence` 等用户可控字段也必须经过过滤；
- 服务请求所需的模型、endpoint 和生成参数。完整 Prompt、完整原始聊天记录和 API Key 不作为日志内容保存。

### 永远不得发送的内容

密码、Token、API Key、私钥、身份证/社会安全号码、银行卡或信用卡信息、精确地址、医疗诊断、病史、用药/处方信息，以及这些内容的常见英文表达，均不得进入远程请求。用户可控字段一旦命中规则，按字段安全失败；历史消息按整条消息安全失败。应用不会记录完整 Prompt、API Key 或原始请求体。

Memory 删除后立即停止检索，因此删除的条目不会作为后续聊天上下文发送；本地 Tombstone 和必要的事件元数据可能保留，用于本机删除语义和未来边界设计。它们仍不自动上传，也不构成当前可用的云端同步。

## Memory 删除与 Event 投影

Memory v1 的本地 Tombstone 保留原 schema 形状，但将 `content`、`evidence` 替换为 `（已删除）`，将 `sourceMessageId` 替换为不含原文的 `deleted:<id>`，并清空 `confidence`、`expiresAt`、`supersedesId`；原始内容、证据和消息文本不留在删除后的事实行中。删除 Event 的 payload 只允许 `{ id }`，其他字段只放必要的操作、实体类型、版本、设备和时间元数据。

删除不会把 Tombstone 放回检索结果。删除前已经产生的安全 upsert Event 可能仍在本机 Outbox 中等待未来传播；当前实现不声称能够回写历史 Event，但这些 Event 不得包含敏感值、原始聊天或完整证据。旧版本已经写入完整删除内容的遗留行只有在再次经过删除/迁移边界时才会被收敛，本契约不把历史存量追溯性地宣称为最小 Tombstone。

## 对象操作契约

| 对象 | 查看 | 编辑 | 禁用 | 删除 | 导出 | 删除后立即消失 |
|---|---|---|---|---|---|---|
| SOUL | 读取宠物包中的只读人格文件 | 修改宠物包源文件/版本 | 移除 `soulPath` 或包能力 | 从宠物包移除文件/引用 | 复制本地包文件 | 下次加载不再进入 Context |
| Preference | 读取本机偏好 JSON/当前上下文 | `upsert` 后写回本机 | 以默认值改写；没有 Memory 式 disabled 行 | 设置入口或“忘掉这个”删除；失败不报成功 | 导出安全的偏好 JSON | 后续偏好读取和新 Context 不再包含 |
| Memory | `list`/`get`/安全检索 | `update` | `disable` | `delete`，写最小 Tombstone 和 delete Event | `export(json/markdown)`，只导出当前允许范围 | `search` 立即排除，后续远程 Context 也排除 |
| Session | 查看当前窗口气泡和草稿 | 编辑草稿；停止/撤回未完成回复 | 不适用 | 退出聊天、换宠或清理运行时状态 | 不导出完整原始会话 | 不转写为长期事实，退出后不再参与 |
| Task | 查看任务/提醒事实 | `updateTask`、重排提醒 | 完成/取消作为状态操作 | 先软删除并产生 delete Event，按产品规则再物理清理 | 导出任务事实，不含敏感字段 | 任务消费者和提醒调度停止使用 |
| Event | 查看本机安全 Outbox 投影 | 不允许直接编辑事实事件 | 不适用 | 事实删除产生 delete Event；传播确认后才可压缩 | 仅导出安全投影 | 不影响事实检索，不能把 Event 当事实源 |

以上是当前边界允许的操作，不等于所有操作已经有完整的用户设置 UI；聊天入口已经通过右键菜单和右键双击提供，但远程 Provider 配置入口、OS Secret Store、Event ack/跨设备同步仍未交付。

服务商是否保存数据、保存多久、是否用于训练以及处理区域政策，不由本应用保证；用户应以服务商当前有效的条款、隐私政策和区域说明为准。当前项目没有云端数据库、同步服务、向量库、队列或账号系统能力。

## 边界与优先级

- SOUL 是宠物包的人格和安全边界，运行时只读；它不是用户事实，也不能覆盖平台安全、工具权限或当前用户意图。
- 偏好是可解释的低风险行为设置（称呼、回复风格、提醒习惯）；Memory 是带来源、证据、置信度和作用域的参考事实。两者都不能覆盖当前输入。
- Session 是短期上下文，Memory 不是完整聊天记录；未明确要求或未确认的推断候选不得进入长期 Memory。
- Task 保存“要做什么、何时做、状态如何”；提醒投递、宠物文案和 Event 都是 Task 的消费者或变更记录，不另建第二个任务事实源。
- Event 只保存脱敏后的变化投影；密码、Token、医疗信息、精确地址、原始聊天和完整证据不得进入 Outbox。`deviceId + syncVersion` 只表示单设备顺序，不表示跨设备因果顺序。

## 对话样例（记住 / 不记住 / 询问）

| 决定 | 用户表达 | 处理 |
|---|---|---|
| 应该记住 | “以后叫我阿星。” | 保存全局偏好 `nickname`，并告诉用户可删除。 |
| 应该记住 | “我喜欢桂花茶，请记住。” | 保存显式 `preference` Memory；不保存整段聊天。 |
| 应该记住 | “记住我们周五一起复盘。” | 保存当前宠物作用域的关系 Memory；若包含日期提醒，另询问是否创建 Task。 |
| 应该记住 | “回答短一点，别太严肃。” | 保存低风险回复风格偏好，不写入关系 Memory。 |
| 应该记住 | “明天下午三点提醒我交报告。” | 创建 Task/Reminder；不要把它复制成普通 Memory。 |
| 不应该记住 | “我今天好累。” | 只在当前 Session 里共情，不持久化。 |
| 不应该记住 | “我的身份证号是 123……” | 拒绝保存，不进入偏好、Memory、Task Event 或模型长期上下文。 |
| 不应该记住 | “我住在某某小区 8 栋。” | 不保存精确地址；如确有提醒需求，只询问更安全的泛化信息。 |
| 不应该记住 | “我吃了什么药，帮我记着。” | 不保存医疗内容；若用户需要时间提醒，先询问是否只创建不含药名的提醒。 |
| 不应该记住 | “我可能下个月想学摄影。” | 不创建 Task/Memory；保持对话，等待明确意图和时间。 |
| 应该询问 | “下周找时间提醒我一下。” | 询问具体事项、日期/时区和是否创建 Task，不默认今天或写入 Memory。 |
| 应该询问 | “记住我最近身体不舒服。” | 说明不保存医疗结论，询问是否需要一个不含健康细节的休息提醒。 |
| 应该询问 | “别再提醒这个。” | 绑定最近可靠的主动投递上下文；没有上下文时询问任务名称，不写普通 Memory。 |
| 应该删除 | “忘掉刚才那条。” | 删除最近一条偏好/Memory；保留必要 Tombstone，确认它不再被检索。 |

这份契约是本地实现的验收边界。跨设备冲突合并、远端 ack、RLS/TLS、向量索引和队列仍属于云同步前置设计，不属于当前可用能力。
